# Codex 仅短信验证

协议驱动从当前 Auth 文档的 `bootstrap-inert-script` 中仅读取两项通道配置，并结合当前会话的 `multi_channel_allowed` 和号码国家作决定。不会执行页面脚本、使用其他账号捕获的开关，或改写服务端资格。

- 页面提供 SMS 选择时，在首次 `add-phone/send` 中提交 `channel=sms`。
- 页面只有默认 SMS、没有通道字段时，按官方表单省略该字段。
- 当前会话和国家仅允许 WhatsApp 时，不强制改成 SMS；已知预选国家时在购号前停止。
- 无法解析当前页面的通道配置时，在购号前停止，不依赖其他会话的缓存或猜测默认通道。
- `set_phone_verification_channel` 属于待验证号码，优先于账号原有的 `phone_verification_channel`。发码后检查本次响应，不能使用之前缓存的通道作结论。
- 发码 HTTP 200 只代表请求接受；必须实际收到短信并通过验证码验证，才算手机验证完成。

SMSBower 的国家、供应商、最高价和购号次数仍严格受任务预算限制。无库存、下单结果不确定、限流、风控或通用 400 不触发自动换号或加价。失败激活需要供应商确认取消；号码类型未知不能写成已经验证为实体 SIM。
