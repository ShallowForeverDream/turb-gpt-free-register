# 本地账号管理操作顺序

## 1. 打开本地页面

在项目目录执行 `webui.cmd start`，浏览器访问 `http://127.0.0.1:5000/`。

如果使用 RoxyBrowser 打开本地管理页，请在 Roxy 地址栏使用
`http://localhost:5000/`；Roxy 的代理扩展可能会把数字回环地址
`127.0.0.1` 错误地送入代理，导致 `ERR_ADDRESS_UNREACHABLE`。应用启动时会
自动为 Roxy 加入回环地址绕过规则，Roxy 控制 API 也不会走系统代理。
如果本机 `.env` 已设置 `WEBUI_LOCAL_NO_AUTH=True`，无需输入授权码。重启服务用 `webui.cmd restart`。

只有本机回环地址可以免登录。开启免登录时不要把绑定地址改为 `0.0.0.0`。

## 2. 核对转发邮箱配置

在“配置 → 邮箱 / OTP”中：

1. “通用邮箱 / OTP”：打开“自动取邮箱+收码”，邮箱来源填写 `imap`，点击该分区的“保存”。
2. “转发 IMAP”：填入统一收件箱的客户端授权码，再点击该分区的“保存”。
3. 回到刚才的分区或刷新页面，确认保存后的值。仅切换开关再切换分区不代表已经保存。

“配置 → 注册方式”是统一运行方式。选择 `roxy`、`cloak`、`browser_use` 或 `skyvern` 后，注册、查活、2FA、换绑、Codex、套餐和 Agent Token 会共用该浏览器驱动；任务开始后会固定驱动，不会中途回退到 `protocol`。浏览器驱动配置不完整时，任务会在入队前提示配置错误。

在“邮箱池 → 导入”选择“转发到同一 IMAP 收件箱”。收件箱地址要和网易网页版顶部显示的完整地址一致：`@yeah.net` 使用 `imap.yeah.net`，`@163.com` 使用 `imap.163.com`，SSL 端口均为 `993`。原 Apple 邮箱逐行填写。

邮箱池页面的复选框支持跨页保留选择：

- 回到“注册”页点击“使用选中邮箱注册”，会按所选邮箱顺序入队；
- 回到“账号”页点击“导入选中邮箱”，会把所选邮箱登记为已注册邮箱账号，之后自动注册不会再次领取它。

已有素材填错收件箱时，可按相同地址清单重新导入以更新连接配置，已有使用状态和账号关联会保留。已注册 GPT 的邮箱可在“账号”页导入；这只是本地登记，不会生成登录凭据，也不能仅凭邮箱地址证明远端已经注册。

## 3. 导入已有账号资料

在“账号 → 导入已注册 GPT 账号”选择 `.xlsx`，表头为“邮箱、密码、2FA、AT”，或粘贴四列文本。
重复邮箱会跳过，空的凭据不会凭空生成。密码是 GPT 密码；2FA 列是长期密钥，不是当前六位动态验证码。

导入只保存本地资料，不能据此证明远端账号可登录、Token 未过期或 2FA 已开启。不要删除已有记录来强行覆盖导入。

## 4. 理解查活结果

查活队列一次只执行一个账号。通常先访问登录入口，然后才可能发验证码、收验证码、验证并保存 AT。

| 页面结果 | 含义与处理 |
| --- | --- |
| 登录入口被拒绝/限流，尚未发码 | 预检遇到 HTTP 403/429；不会等待 IMAP，不代表账号已失效。此处停止自动请求，改用正常网页登录。 |
| 入口受阻 | 当前 `REGISTRATION_DRIVER=protocol` 时，`curl_cffi` 自动化协议指纹可能被 Cloudflare 拒绝；这不等于代理端口不可达。浏览器能打开而 protocol 仍 403 时，应启用已配置的浏览器驱动（Roxy/Cloak/Browser Use）后再重试。 |
| 已注册账号 | OTP 验证后返回 workspace 页，说明邮箱已有 ChatGPT 账号。程序会跳过创建账号，选择默认组织工作区并登记/更新账号 AT。 |
| 访问被拒绝/限流 | 已进入认证阶段后被拒绝；查看日志确认阶段，通过网页登录处理。 |
| 待完成工作区选择 | 只有没有可用工作区清单、多个同类工作区未指定，或选择接口没有下一跳时才会出现。账号页“更多 → 登录工作区”可保存“组织工作区（默认）”“个人工作区”或具体组织；下一次查活会自动提交选择并继续 OAuth 回调。 |
| IMAP 登录失败 | 检查完整收件邮箱、服务器和客户端授权码；不要用网页登录密码替代授权码。 |
| 等待 OTP 超时 | 检查转发邮件是否实际到达，是否保留了对应 Apple 地址的原收件人。不要拿另一账号的验证码代填。 |
| 无 Token | 本地没有 AT；“批量开 2FA”会跳过，不是已开启。 |
| 注册入口 HTTP 403 | 这是代理/Cloudflare 入口拒绝，不是“邮箱已注册”的证明；任务会把未消耗的邮箱放回可用。先换稳定出口或正常网页登录，不要连续重试同一节点。 |

403/429 不会再进行预检重试或改用直连重放。页面出现“已注册”、查活队列完成、导入成功，都不等于完成 2FA。

## 5. 依次完成正常登录和 MFA

1. 打开 [ChatGPT](https://chatgpt.com/)，一次处理一个账号。
2. 使用这个账号原来的登录方式。如果注册时使用“通过 Apple 登录”，继续使用相同 Apple ID；不要仅因地址以 `@icloud.com` 结尾就假设它使用 Apple 登录。
3. 网页确实要求邮箱验证码时，到已配置的转发收件箱查看发给当前 Apple 地址的最新邮件，在该网页中输入验证码。
4. 登录成功后进入“设置 → 安全与登录 / Security and login → 多重身份验证 / MFA”，选择验证器应用并按网页提示完成设置。
5. 网页显示开启成功后，再退出当前账号并处理下一个。妥善保管页面提供的恢复方式。

菜单及可用验证方式可能因账号而不同。参考 [OpenAI MFA 说明](https://help.openai.com/en/articles/7967234-managing-multi-factor-authentication-mfa) 和 [登录方式说明](https://help.openai.com/en/articles/4936824-can-i-change-how-i-log-into-my-account-authentication-method)。

正常浏览器同样无法登录时，通过 [OpenAI 帮助中心](https://help.openai.com/) 处理访问或账号问题；邮箱接收正常不能消除登录页的访问拒绝。网页设置完成不会自动同步本地 2FA 密钥，不要因此重复点击本地“批量开 2FA”。
