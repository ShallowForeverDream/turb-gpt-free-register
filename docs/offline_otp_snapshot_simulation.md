# 验证码快照差分的离线模拟

## 范围

`tests/test_offline_otp_snapshot_simulation.py` 是独立的虚构数据测试，不导入注册器、邮件适配器或账号数据库。

模拟顺序为：发码前保存已有验证码集合，在虚拟时间 0 秒记录发码标记，虚拟等待 60 秒后读取另一份集合，再排除旧码。只有一个新增值时记作候选；多个新增值单独报告歧义，不假设接口列表的排序含义。

模拟不会真实发码、取信、提交验证码或重试认证。直接运行脚本时，任何意外的 socket 连接都会使测试失败。它不替换生产取码策略，也不代表真实注册流程已经修复。

## 运行

在项目目录运行单元测试：

```powershell
.\.venv\Scripts\python.exe -m unittest tests.test_offline_otp_snapshot_simulation -v
```

运行独立实验并生成逐例 Markdown、JSON 报告：

```powershell
.\.venv\Scripts\python.exe tests\test_offline_otp_snapshot_simulation.py --report-dir run\diagnostics\otp-snapshot-simulation-20261027
```

报告写入 Git 忽略的 `run/` 目录。60 秒使用虚拟时钟，不需要实际等待一分钟。

## 固定场景结果

8 项单元测试覆盖 15 个固定场景：

| 场景类别 | 数量 | 候选选择的实际结果 |
| --- | ---: | --- |
| 正常到达、59 秒到达、空邮箱、前导零 | 4 | 正确选出候选 |
| 没有新邮件、完整列表重新排序 | 2 | 正确地没有选出候选 |
| 本次邮件 95 秒才到 | 1 | 60 秒时没有候选，不能断言发送失败 |
| 接口缓存未刷新、新邮件再次使用相同数值 | 2 | 邮件已到，但差分漏选 |
| 发码前快照不完整、前次请求邮件晚到、收件人混淆 | 3 | 差分选中了非本次邮件的数值 |
| 出现多个不同新增值 | 1 | 无法唯一确定候选 |
| 发码前读取失败、发码后读取失败 | 2 | 单独报告读取错误，不当作空邮箱或未收件 |

“测试通过”表示每个场景都产生了预期结果，包括预期的误选和漏选；不是说 15 个场景均能正确取码。

## 结论

快照完整、接口及时刷新、收件人正确、没有旧请求晚到且只有一个新增值时，差分方案能选出正确候选。算法本身不需要邮件 ID 或时间作为输入。

但同样的两份验证码集合可以对应不同的邮件归属。例如，`111111` 变成 `111111、222222`，既可能是本次邮件，也可能是上次请求的邮件迟到。仅凭数值集合不能区分。

这些是构造的边界案例，不证明真实供应商存在对应问题，案例占比也不能用作线上成功率或错误率。邮件时间和 ID 是额外证据，同样不能单独解决所有请求归属问题。
