# 2FA 首次发码、日志筛选与全流程进度

## 2FA 发码

- 与注册共用页面初始化逻辑：跟随授权导航后，读取本次验证页的服务端路由会话。
- 只有 `passwordless_email_otp_send_pending=true` 且邮箱、会话、页面和模式匹配时，才执行一次正常的页面首次发码。它不是 `/email-otp/send` 或 `/email-otp/resend`。
- 没有待首次发送标志时，不额外发送；未到验证页则停止，不盲等。
- ICAPI 从验证页就绪（如有首次发码，则以请求确认完成为准）后等待30秒，最多直接读取三次，无基线、无主动重发。三次未取码报“验证码未获取”；验证码被拒绝也不再启动另一轮三次读取。
- 2FA 的邮箱重认证仍是独立验证，不能复用注册 OTP。邮箱超时直接终止，不再额外重发。

运行策略检查接口 `/api/runtime/registration` 增加 `twofa_otp_delivery=page_state_initial_delivery_no_resend`，用于区分磁盘改动与进程实际加载版本。

- 历史列表：邮箱/精确任务 ID、原始任务状态、创建日期范围；过滤条件在 SQL COUNT/LIMIT/OFFSET 之前应用，翻页和刷新保留条件。失败包含网络与收码异常，行内仍展示原有细分状态。
- 原始日志：级别、注册/2FA/Codex 流程、关键词；复制/下载保留完整原始日志，并有“返回可视化日志”按钮。
- 可视化按注册、2FA、Codex 授权分组，当前/失败部分自动展开，已完成与跳过部分可点击展开。包含邮箱发码、API/邮箱收码、OTP 验证、TOTP 激活、Codex 手机短信/接码、工作区和回调节点。
- Codex 未启用时按已保存状态显示“跳过”；Codex 成功且没有发生手机验证时，短信节点显示“跳过”，不冒充已接码。
- 结合本次日志与账号的状态字段，2FA 未完成时不再把整个任务显示成注册完成；保留原任务追加日志时，只分析最后一次注册尝试。旧失败记录不会借用后来才创建的账号显示成功。
- 进度接口仅增加状态字段，不返回账号 Token、TOTP Secret；新旧两套 UI 共用这些逻辑。
